# BLR source-only test inventory

These blocks inspect repository assets and execute in source-tree development and fast CI. When a checkout is unavailable they skip through `blr_repo_path()` with the explicit source-tree reason. No scientific or public-contract owner is source-only.

| Test owner | Blocks | Repository assets | Reason |
|---|---|---|---|
| Phase 3/4/6/8/9C/9E/9G/10D | core/converter/header singularity and protected-source hashes | `src/`, `R/`, `NAMESPACE` | implementation architecture, not installed behavior |
| Phase 11D/13E/14E/15B/16A/17A | packed-BED route structure, dispositions, inventories, protected hashes | `src/`, `docs/dev/`, `tools/`, `NAMESPACE` | maintenance evidence |
| Phase 12A | documentation, workflow, benchmark and peak-RSS tooling | `docs/dev/`, `.github/`, `tools/` | repository/CI contract |
| Phase 17B–17J | typed MT boundaries, source call graph, workflow and developer-contract text | `src/`, `R/`, `docs/dev/`, `.github/`, `tools/` | binding-neutral/source architecture |
| annotation backend design | design-document assertions | `docs/dev/` | developer documentation |
| individual BayesRC | shared-header inclusion | `src/` | source composition |
| Phase 3/4 runtime MD5 | toolchain-specific serialized runtime identity | source fixture harness and same compiler | developer-tier bitwise evidence |
| Phase 17K | binding-neutral type singularity, scalar source integration, public-routing and research disposition | `src/`, `R/` | repository architecture; numerical filter/oracle tests remain portable |

Portable fixture MD5 checks, numerical references, public schemas, alignment, update controls, reproducibility, and scientific identities are not in this inventory and remain installed-check requirements.
