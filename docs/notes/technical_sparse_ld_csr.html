Technical Appendix: Sparse LD and CSR

Author
Affiliation

Peter Sørensen

Aarhus University

This appendix defines the sparse linkage disequilibrium (LD) representation used by the current sblr BED-to-CSR workflow. It describes the statistical matrix, compressed sparse row (CSR) structure, disk-backed construction, indexing conventions, alignment requirements, and downstream conversion used by stblr_csr() and related wrappers.

The stable user-facing contract is deliberately narrower than the current binary-file implementation:

  1. create sparse LD with make_sparseLD(), which records metadata in Glist$sparseLD;
  2. inspect the resulting prefix with sparseLD_read_CSR() when needed; and
  3. pass the updated Glist to stblr_csr() or stblr_csr_annot().

sparseLD_stream_CSR() is the lower-level writer used by the preparation helper. Its ld_prefix remains the disk-backed artifact identifier, but the current high-level workflow carries that prefix through Glist$sparseLD.

The present file suffixes, integer widths, floating-point widths, metadata keys, and upper-triangle storage convention are documented here to explain behavior and support validation. They should not be treated as a guaranteed manual file-format API. Use package readers, writers, and samplers rather than editing or independently constructing these files.

From BED Genotypes to Sufficient Statistics and Sparse LD

For genotype matrix \(X\), phenotype vector \(y\), and marker effects \(b\), a summary-statistics marker sampler needs quantities including

\[ wy=X^\top y, \qquad ww_i=x_i^\top x_i, \qquad yy=y^\top y, \]

and enough off-diagonal marker information to update

\[ r=X^\top(y-Xb)=wy-X^\top Xb. \]

In the BED-derived workflow, these inputs are prepared in two coordinated branches:

the same BED files + cls + rows + allele frequencies
    |
    +--> make_stats() ------> stats$wy, stats$ww, stats$yy
    |
    +--> make_sparseLD() ---> Glist$sparseLD$prefix
                                      |
                                      v
                       stblr_csr(stats = stats, Glist = Glist, ...)

make_stats() supplies the phenotype cross-products and diagonal marker cross-products. make_sparseLD() supplies retained off-diagonal marker correlations and records their prefix and metadata in Glist$sparseLD. During CSR model setup, the sampler combines the stored correlations with stats$ww to recover the corresponding off-diagonal cross-product scale.

This split is important: the on-disk values are correlations, not raw \(X_i^\top X_j\), and the diagonal cross-products are supplied separately by stats$ww.

Matrix Represented by the Current Writer

The current BED sparse-LD writer standardizes each selected marker using its allele frequency, mean-imputes missing genotypes to zero on that standardized scale, computes marker cross-products, and normalizes off-diagonal entries to correlations:

\[ r_{ij} = \frac{x_i^\top x_j} {\sqrt{(x_i^\top x_i)(x_j^\top x_j)}}. \]

The writer retains an off-diagonal pair \(i<j\) when it passes the configured distance rules and

\[ r_{ij}^2 \geq \texttt{r2_threshold}. \]

The stored value is signed \(r_{ij}\), not \(r_{ij}^2\). The current streamed artifact stores:

  • only the upper triangle, \(j>i\);
  • no explicit diagonal entries;
  • an implicit diagonal correlation of one; and
  • only pairs passing the threshold and window rules.

Thus the disk artifact is a sparse, upper-triangle, correlation-like representation of LD. It is not itself the complete \(X^\top X\) matrix.

When a CSR ST-BLR sampler opens the prefix, it reads the stored correlation and constructs a symmetric in-memory neighbor structure. For each retained pair it converts

\[ r_{ij} \quad\longrightarrow\quad \widetilde{X_i^\top X_j} = r_{ij}\sqrt{ww_iww_j}. \]

The diagonal contribution remains ww[i]. This is why the sparse-LD prefix and sufficient statistics must use compatible samples, marker scaling, and marker order. The current shared-LD ST-BLR setup also requires compatible ww across trait columns.

What CSR Means

Compressed sparse row format represents a sparse matrix without allocating all \(m^2\) entries. Three arrays describe the retained entries:

Array Current conceptual role
row_ptr Cumulative offsets delimiting each row’s retained entries; length \(m+1\).
col_idx Column index for every retained entry; length nnz.
values Value for every retained entry; length nnz.

For zero-based row pointers, entries belonging to row \(i\) occupy positions

\[ \texttt{row\_ptr}[i] \quad\text{through}\quad \texttt{row\_ptr}[i+1]-1. \]

For example, consider the upper-triangle entries

row 0: (column 1, 0.40), (column 3, -0.20)
row 1: (column 3, 0.15)
row 2: no retained entries
row 3: no retained entries

Their CSR arrays are conceptually:

row_ptr = [0, 2, 3, 3, 3]
col_idx = [1, 3, 3]
values  = [0.40, -0.20, 0.15]

row_ptr is always a cumulative pointer array. The one_based option of sparseLD_read_CSR() converts returned column indices for convenient R inspection; it does not convert the row pointers.

Why Disk-Backed Sparse CSR Is Used

A dense \(m\times m\) LD matrix requires \(O(m^2)\) storage. This becomes prohibitive for genome-scale marker sets even when most scientifically useful LD relationships are local or sufficiently strong.

Sparse CSR reduces storage toward \(O(m+\mathrm{nnz})\), where nnz is the number of retained off-diagonal upper-triangle entries. Disk-backed storage provides two additional advantages:

  • the resulting LD artifact can be reused by multiple CSR model fits; and
  • the complete sparse arrays do not have to be returned to or retained in R during construction.

sparseLD_stream_CSR() processes marker blocks, computes candidate cross-products for block pairs, applies distance and \(r^2\) rules, and writes retained entries incrementally. It still needs working memory for decoded genotype blocks and block cross-products, but it avoids constructing either a dense whole-genome LD matrix or the complete sparse result in R.

Stable User-Facing Contract

The supported workflow treats the sparse-LD artifact as an opaque package- managed object identified by a prefix:

ld_prefix <- file.path(output_dir, "chr1_ld")

sparseLD_stream_CSR(
  bed_files = Glist$bedfiles[chr],
  n = Glist$n,
  cls = list(cls),
  out_prefix = ld_prefix,
  rows = NULL,
  af = list(Glist$af[[chr]][cls]),
  r2_threshold = 0.001,
  block_size = 1024,
  nthreads = 4
)

The stable usage expectations are:

  • all files belonging to a prefix are created and retained together;
  • sparseLD_read_CSR(ld_prefix) is used for inspection and validation;
  • stblr_csr(..., Glist = Glist) and stblr_csr_annot() normally consume it through Glist$sparseLD$prefix; explicit ld_prefix remains available for lower-level workflows;
  • marker order and construction settings are recorded externally; and
  • package functions handle file naming, binary types, index bases, diagonal convention, and conversion to sampler structures.

Analysis code should not assume that current suffixes, metadata keys, or binary encodings will remain unchanged. Independent tools that manually write these files depend on implementation details and can silently become incompatible after package changes.

ld_prefix and the Current Disk Artifact

ld_prefix is a common path prefix, not a single file and not an in-memory matrix. The current implementation derives several files from it. For example, a prefix path/chr1_ld currently identifies:

path/chr1_ld.row_ptr.u64.bin
path/chr1_ld.col_idx.u32.0based.bin
path/chr1_ld.values.f32.bin
path/chr1_ld.meta.txt

These names expose current implementation details:

  • row pointers are currently unsigned 64-bit integers;
  • column indices are currently unsigned 32-bit zero-based integers;
  • stored correlations are currently 32-bit floating-point values; and
  • metadata is currently a text file describing dimensions and settings.

The metadata currently records fields such as marker count, nnz, triangle and diagonal conventions, value type, normalization, threshold, distance limits, block size, thread count, and used sample count.

Treat the complete prefix as one artifact. Do not mix files from separate runs. Do not overwrite an important prefix when changing samples, marker sets, allele frequencies, distance windows, or thresholds. Prefer distinct, descriptive prefixes and retain construction provenance beside them.

Exported and Internal Helpers

Current NAMESPACE and wrapper status distinguish the supported public path from lower-level generated functions:

Helper Current role Current status
sparseLD_stream_CSR() Computes BED-derived sparse LD and streams the disk-backed prefix. Exported lower-level writer used by make_sparseLD().
sparseLD_read_CSR() Reads a written prefix into R for inspection and validation. Exported; user-facing reader.
sparseLD_to_CSR() Computes the same upper-triangle sparse representation and returns arrays in memory. Generated lower-level wrapper; not exported in the current NAMESPACE.
sparseLD_write_CSR() Delegates to sparseLD_stream_CSR() with an output prefix. Generated alias/internal wrapper; not exported in the current NAMESPACE.

The lower-level wrappers can be useful during development, but they are not the documented model handoff. In particular, stblr_csr() accepts ld_prefix, not an R list returned by sparseLD_to_CSR().

The package also contains older or separate CSR conversion code for other LD inputs. Its conventions should not be assumed to be identical to the BED-streamed prefix described here.

Sparse-LD Construction Settings

Sparse-LD settings affect memory, runtime, disk use, and the statistical approximation. They should be selected deliberately and reported with model results.

Marker and Sample Selection

bed_files
Paths to one or more PLINK BED files. Their corresponding cls entries define the concatenated model-marker order.
n
Number of individuals encoded by the BED source.
cls
A list of marker-column index vectors, one per BED file. The order within and across these vectors becomes the sparse-LD row and column order.
rows
Optional positive one-based sample indices. When supplied, LD is computed from this selected sample. The same sample selection must underlie the sufficient statistics used downstream.
af
Optional list of allele frequencies aligned to cls. When omitted, the writer computes allele frequencies from the selected packed genotypes. Supplied values must be finite and in \([0,1]\). Missing genotypes are represented as zero after standardization, corresponding to mean imputation on that scale.

Threshold and Window Settings

r2_threshold
Minimum squared correlation for retaining an eligible pair. The writer compares \(r_{ij}^2\) with this value but stores signed \(r_{ij}\). A larger threshold produces a sparser approximation and may remove weak but collectively relevant LD.
max_distance_variants
Maximum difference in model-order marker indices. Positive values restrict retained pairs to this index window. A value of zero disables this restriction in the current implementation.
max_distance_bp
Maximum base-pair separation when positions are supplied. Positive values restrict retained pairs by physical distance. A value of zero disables this restriction. The implementation evaluates forward position differences, so pos_bp should be aligned to marker order and ordered consistently within the intended genomic segments.
pos_bp
Optional list of marker base-pair positions aligned to cls. When absent, the base-pair distance restriction cannot be applied, even if max_distance_bp is positive.

A pair must pass every enabled window rule before its \(r^2\) is tested. Disabling both distance restrictions permits all upper-triangle marker pairs to be considered and can be computationally expensive. The exported R wrapper fails closed in this case unless allow_full_ld = TRUE is supplied explicitly.

Computational Settings

block_size
Number of markers decoded and compared in a working block. Larger values can improve matrix-multiplication efficiency but increase working memory roughly through genotype-block and block-cross-product buffers. It changes the construction strategy, not the intended retention rule.
nthreads
Requested OpenMP thread count. It affects construction performance and may affect low-level floating-point execution details, but it is not an LD threshold or model-prior parameter.

Scaling

sparseLD_stream_CSR() does not expose a scale argument. The current writer always constructs its correlation values from allele-frequency-standardized markers. By contrast, bed_xtx_xty() exposes scale. For the standard BED-to-CSR handoff, use compatible standardized marker statistics:

stats <- bed_xtx_xty(..., af = af, scale = TRUE)
sparseLD_stream_CSR(..., af = list(af))

Using bed_xtx_xty(..., scale = FALSE) with the current standardized correlation writer changes the scale relationship assumed when the sampler combines r_ij with stats$ww. Such combinations require explicit validation rather than being assumed compatible.

Streaming and Blocking Behavior

The writer reads the selected BED markers into a packed representation, then works through pairs of marker blocks. For each eligible block pair it:

  1. decodes standardized marker values into floating-point working buffers;
  2. computes raw block cross-products with matrix multiplication;
  3. converts each eligible cross-product to correlation \(r_{ij}\);
  4. applies distance and \(r^2\) retention rules; and
  5. appends retained upper-triangle column indices and values to disk.

After each row, it writes the cumulative retained-entry count to row_ptr. Consequently, the final row pointer equals nnz.

Streaming avoids holding the final col_idx and values arrays in R or in one complete native in-memory result. It does not eliminate all memory or runtime costs: the packed selected genotype matrix, diagonal cross-products, decoded blocks, and block cross-products still require resources. The number of candidate block pairs can also become large when windows are wide or disabled.

Index Bases and Diagonal Convention

Three conventions must be distinguished:

  1. rows and cls supplied from R use the documented R-facing indexing expected by their wrappers.
  2. Current on-disk col_idx entries are zero-based.
  3. sparseLD_read_CSR(prefix, one_based = TRUE) returns one-based column indices for convenient R inspection.

The reader’s one_based argument changes only the returned col_idx vector. row_ptr remains a zero-based cumulative pointer array whose first value is zero and whose final value is nnz.

The current streamed artifact omits diagonal entries and reports diag = "implicit_1". Downstream ST-BLR samplers use the supplied stats$ww for diagonal \(X_i^\top X_i\) contributions. Users inspecting the sparse arrays should not mistake absence of explicit diagonal entries for a zero diagonal.

Package functions validate and handle these conventions. Manual index conversion or insertion of diagonal values risks corrupting the expected contract.

Marker-Order, Sample, and Scaling Invariants

Sparse arrays contain positional indices, not biological marker identifiers. The most important cross-layer invariant is:

Glist$rsids[[chr]][cls]
    == Glist$rsidsLD[[chr]]
    == rows of stats$wy and stats$ww
    == rows and columns of sparse LD
    == rows of an annotation matrix A
    == rows of fit$bm and fit$dm

Establish and retain marker order explicitly:

marker_id <- Glist$rsidsLD[[chr]]
cls <- match(marker_id, Glist$rsids[[chr]])

stopifnot(
  !anyNA(cls),
  identical(Glist$rsids[[chr]][cls], marker_id)
)

For multiple BED files, the concatenation of cls[[1]], cls[[2]], and so on defines the CSR order. Allele-frequency and position lists must follow the same per-file and concatenated order.

The same selected sample must underlie LD and sufficient statistics. If rows is used, apply it consistently. If allele frequencies are supplied, they must correspond to that construction and marker order. If annotations are later used, align their rows before fitting:

rownames(A) <- marker_id
stopifnot(identical(rownames(A), marker_id))

A permutation error can produce dimensionally valid CSR files and model fits while assigning LD or annotations to the wrong markers. Dimension checks alone cannot detect this error.

Reading and Validating a Prefix

Use the exported reader to inspect a prefix without manually decoding the binary files:

ld <- sparseLD_read_CSR(ld_prefix, one_based = TRUE)

stopifnot(
  ld$nrow == length(cls),
  ld$ncol == length(cls),
  length(ld$row_ptr) == length(cls) + 1L,
  length(ld$col_idx) == length(ld$values),
  tail(ld$row_ptr, 1) == length(ld$values),
  ld$index_base == 1,
  identical(ld$diag, "implicit_1")
)

The current reader checks that required metadata dimensions exist, reads the expected byte counts, verifies that row pointers begin at zero and end at nnz, requires nondecreasing row pointers, checks column-index bounds, and rejects non-finite values.

Additional analysis-level validation should confirm:

  1. cls contains no missing marker matches.
  2. LD dimensions equal the intended marker count.
  3. row_ptr has length \(m+1\).
  4. col_idx and values have equal length.
  5. the final row pointer equals nnz.
  6. returned index_base matches how col_idx is being inspected.
  7. the upper-triangle and implicit-diagonal conventions are understood.
  8. values are finite signed correlations and remain within plausible correlation bounds.
  9. n_used, thresholds, windows, and marker count match the intended run.
  10. stats$wy, every stats$ww vector, annotations, and posterior rows use exactly the same marker order.

The reader can validate structural properties but cannot prove that the BED source, allele frequencies, sample rows, phenotypes, annotations, or marker identities are scientifically aligned. Retain that provenance separately.

How stblr_csr() Consumes the Prefix

The public model handoff is short:

fit <- stblr_csr(
  stats = stats,
  Glist = Glist,
  scheduled = FALSE
)

During setup, the current ST-BLR CSR implementation:

  1. checks that metadata marker count matches the model marker count;
  2. reads the zero-based upper-triangle arrays;
  3. validates row pointers, column bounds, finite correlations, and positive stats$ww;
  4. ignores any explicit self-pairs if encountered;
  5. converts retained \(r_{ij}\) to \(r_{ij}\sqrt{ww_iww_j}\); and
  6. creates a symmetric in-memory neighbor structure for residual updates.

For marker effect \(b_i\), the diagonal residual contribution uses \(ww_i b_i\), while retained off-diagonal neighbors use the converted cross-product values. Missing off-diagonal entries are treated as zero in the sparse approximation.

Annotation-aware CSR wrappers use the same LD prefix and marker-order contract. Their differences concern prior structure, not CSR construction.

Scheduled Sparse Updates

stblr_csr(..., scheduled = TRUE) uses a scheduled marker-update implementation that can revisit likely null markers less frequently and wake retained LD neighbors after an effect change. Settings such as full_sweep_every, candidate_threshold, candidate_lifetime, null_skip_base, null_skip_max, and LD-neighbor wake-up controls affect the sampler’s computational schedule.

These controls are separate from CSR construction settings:

  • r2_threshold and distance windows determine which LD edges exist;
  • scheduling controls determine when markers and retained neighbors are reconsidered during MCMC.

Both can affect finite-run behavior and performance. The statistical prior is unchanged by choosing a scheduled path, but aggressive sparse scheduling must be checked for adequate mixing and sensitivity. See Single-trait models for the scheduling controls.

Sparse LD as an Approximation

The sparse matrix replaces unretained off-diagonal relationships with zero. Approximation enters through:

  • \(r^2\) thresholding;
  • marker-index and physical-distance windows;
  • finite-sample LD estimation;
  • allele-frequency estimation and missing-genotype handling;
  • 32-bit storage of retained correlation values; and
  • any difference between the sample or scaling used for LD and sufficient statistics.

Increasing r2_threshold or narrowing windows usually reduces nnz, runtime, and disk use, but can remove LD needed to represent the conditional marker likelihood adequately. Lower thresholds and wider windows preserve more LD at greater computational cost. There is no universally correct threshold; its adequacy depends on marker density, LD structure, sample size, phenotype architecture, and inferential target.

BED-Versus-CSR Comparison and Reproducibility

When both paths use the same BED source, markers, samples, phenotype, standardization, and priors, stblr_bed() and stblr_csr() should usually show qualitatively comparable posterior patterns. Exact equality is not expected because:

  • the CSR path omits unretained LD;
  • BED and CSR samplers maintain residual information differently;
  • update scheduling and initialization can differ;
  • retained correlations use finite precision; and
  • MCMC introduces Monte Carlo variation.

A comparison should examine PIP rankings, posterior mean effects, aggregate variance summaries, and sensitivity to thresholds rather than equality of individual samples.

For reproducibility, retain:

  • immutable identifiers for BED inputs and selected samples;
  • marker IDs in exact CSR order;
  • cls, rows, allele frequencies, and positions;
  • sufficient-statistic dimensions and scaling choices;
  • all files belonging to ld_prefix;
  • the writer’s returned summary and metadata;
  • package version and platform information; and
  • model priors, MCMC settings, scheduling controls, and seeds.

The current workflow scripts use demonstration-scale settings. Production analyses require sensitivity checks for LD construction and sampler settings, longer chains, and convergence diagnostics.

```text
path/chr1_ld.meta.txt
```

These names expose current implementation details:

- row pointers are currently unsigned 64-bit integers;
- column indices are currently unsigned 32-bit zero-based integers;
- stored correlations are currently 32-bit floating-point values; and
- metadata is currently a text file describing dimensions and settings.

The metadata currently records fields such as marker count, `nnz`, triangle
and diagonal conventions, value type, normalization, threshold, distance
limits, block size, thread count, and used sample count.

Treat the complete prefix as one artifact. Do not mix files from separate
runs. Do not overwrite an important prefix when changing samples, marker
sets, allele frequencies, distance windows, or thresholds. Prefer distinct,
descriptive prefixes and retain construction provenance beside them.

## Exported and Internal Helpers

Current `NAMESPACE` and wrapper status distinguish the supported public path
from lower-level generated functions:

| Helper | Current role | Current status |
|---|---|---|
| `sparseLD_stream_CSR()` | Computes BED-derived sparse LD and streams the disk-backed prefix. | Exported lower-level writer used by `make_sparseLD()`. |
| `sparseLD_read_CSR()` | Reads a written prefix into R for inspection and validation. | Exported; user-facing reader. |
| `sparseLD_to_CSR()` | Computes the same upper-triangle sparse representation and returns arrays in memory. | Generated lower-level wrapper; not exported in the current `NAMESPACE`. |
| `sparseLD_write_CSR()` | Delegates to `sparseLD_stream_CSR()` with an output prefix. | Generated alias/internal wrapper; not exported in the current `NAMESPACE`. |

The lower-level wrappers can be useful during development, but they are not
the documented model handoff. In particular, `stblr_csr()` accepts
`ld_prefix`, not an R list returned by `sparseLD_to_CSR()`.

The package also contains older or separate CSR conversion code for other LD
inputs. Its conventions should not be assumed to be identical to the
BED-streamed prefix described here.

## Sparse-LD Construction Settings

Sparse-LD settings affect memory, runtime, disk use, and the statistical
approximation. They should be selected deliberately and reported with model
results.

### Marker and Sample Selection

`bed_files`
: Paths to one or more PLINK BED files. Their corresponding `cls` entries
  define the concatenated model-marker order.

`n`
: Number of individuals encoded by the BED source.

`cls`
: A list of marker-column index vectors, one per BED file. The order within
  and across these vectors becomes the sparse-LD row and column order.

`rows`
: Optional positive one-based sample indices. When supplied, LD is computed
  from this selected sample. The same sample selection must underlie the
  sufficient statistics used downstream.

`af`
: Optional list of allele frequencies aligned to `cls`. When omitted, the
  writer computes allele frequencies from the selected packed genotypes.
  Supplied values must be finite and in $[0,1]$. Missing genotypes are
  represented as zero after standardization, corresponding to mean
  imputation on that scale.

### Threshold and Window Settings

`r2_threshold`
: Minimum squared correlation for retaining an eligible pair. The writer
  compares $r_{ij}^2$ with this value but stores signed $r_{ij}$. A larger
  threshold produces a sparser approximation and may remove weak but
  collectively relevant LD.

`max_distance_variants`
: Maximum difference in model-order marker indices. Positive values restrict
  retained pairs to this index window. A value of zero disables this
  restriction in the current implementation.

`max_distance_bp`
: Maximum base-pair separation when positions are supplied. Positive values
  restrict retained pairs by physical distance. A value of zero disables this
  restriction. The implementation evaluates forward position differences,
  so `pos_bp` should be aligned to marker order and ordered consistently
  within the intended genomic segments.

`pos_bp`
: Optional list of marker base-pair positions aligned to `cls`. When absent,
  the base-pair distance restriction cannot be applied, even if
  `max_distance_bp` is positive.

A pair must pass every enabled window rule before its $r^2$ is tested.
Disabling both distance restrictions permits all upper-triangle marker pairs
to be considered and can be computationally expensive. The exported R wrapper
fails closed in this case unless `allow_full_ld = TRUE` is supplied explicitly.

### Computational Settings

`block_size`
: Number of markers decoded and compared in a working block. Larger values
  can improve matrix-multiplication efficiency but increase working memory
  roughly through genotype-block and block-cross-product buffers. It changes
  the construction strategy, not the intended retention rule.

`nthreads`
: Requested OpenMP thread count. It affects construction performance and may
  affect low-level floating-point execution details, but it is not an LD
  threshold or model-prior parameter.

### Scaling

`sparseLD_stream_CSR()` does not expose a `scale` argument. The current writer
always constructs its correlation values from allele-frequency-standardized
markers. By contrast, `bed_xtx_xty()` exposes `scale`. For the standard
BED-to-CSR handoff, use compatible standardized marker statistics:

```r
stats <- bed_xtx_xty(..., af = af, scale = TRUE)
sparseLD_stream_CSR(..., af = list(af))
```

Using `bed_xtx_xty(..., scale = FALSE)` with the current standardized
correlation writer changes the scale relationship assumed when the sampler
combines `r_ij` with `stats$ww`. Such combinations require explicit
validation rather than being assumed compatible.

## Streaming and Blocking Behavior

The writer reads the selected BED markers into a packed representation, then
works through pairs of marker blocks. For each eligible block pair it:

1. decodes standardized marker values into floating-point working buffers;
2. computes raw block cross-products with matrix multiplication;
3. converts each eligible cross-product to correlation $r_{ij}$;
4. applies distance and $r^2$ retention rules; and
5. appends retained upper-triangle column indices and values to disk.

After each row, it writes the cumulative retained-entry count to `row_ptr`.
Consequently, the final row pointer equals `nnz`.

Streaming avoids holding the final `col_idx` and `values` arrays in R or in
one complete native in-memory result. It does not eliminate all memory or
runtime costs: the packed selected genotype matrix, diagonal cross-products,
decoded blocks, and block cross-products still require resources. The number
of candidate block pairs can also become large when windows are wide or
disabled.

## Index Bases and Diagonal Convention

Three conventions must be distinguished:

1. `rows` and `cls` supplied from R use the documented R-facing indexing
   expected by their wrappers.
2. Current on-disk `col_idx` entries are zero-based.
3. `sparseLD_read_CSR(prefix, one_based = TRUE)` returns one-based column
   indices for convenient R inspection.

The reader's `one_based` argument changes only the returned `col_idx` vector.
`row_ptr` remains a zero-based cumulative pointer array whose first value is
zero and whose final value is `nnz`.

The current streamed artifact omits diagonal entries and reports
`diag = "implicit_1"`. Downstream ST-BLR samplers use the supplied `stats$ww`
for diagonal $X_i^\top X_i$ contributions. Users inspecting the sparse
arrays should not mistake absence of explicit diagonal entries for a zero
diagonal.

Package functions validate and handle these conventions. Manual index
conversion or insertion of diagonal values risks corrupting the expected
contract.

## Marker-Order, Sample, and Scaling Invariants

Sparse arrays contain positional indices, not biological marker identifiers.
The most important cross-layer invariant is:

```text
Glist$rsids[[chr]][cls]
    == Glist$rsidsLD[[chr]]
    == rows of stats$wy and stats$ww
    == rows and columns of sparse LD
    == rows of an annotation matrix A
    == rows of fit$bm and fit$dm
```

Establish and retain marker order explicitly:

```r
marker_id <- Glist$rsidsLD[[chr]]
cls <- match(marker_id, Glist$rsids[[chr]])

stopifnot(
  !anyNA(cls),
  identical(Glist$rsids[[chr]][cls], marker_id)
)
```

For multiple BED files, the concatenation of `cls[[1]]`, `cls[[2]]`, and so
on defines the CSR order. Allele-frequency and position lists must follow the
same per-file and concatenated order.

The same selected sample must underlie LD and sufficient statistics. If
`rows` is used, apply it consistently. If allele frequencies are supplied,
they must correspond to that construction and marker order. If annotations
are later used, align their rows before fitting:

```r
rownames(A) <- marker_id
stopifnot(identical(rownames(A), marker_id))
```

A permutation error can produce dimensionally valid CSR files and model fits
while assigning LD or annotations to the wrong markers. Dimension checks
alone cannot detect this error.

## Reading and Validating a Prefix

Use the exported reader to inspect a prefix without manually decoding the
binary files:

```r
ld <- sparseLD_read_CSR(ld_prefix, one_based = TRUE)

stopifnot(
  ld$nrow == length(cls),
  ld$ncol == length(cls),
  length(ld$row_ptr) == length(cls) + 1L,
  length(ld$col_idx) == length(ld$values),
  tail(ld$row_ptr, 1) == length(ld$values),
  ld$index_base == 1,
  identical(ld$diag, "implicit_1")
)
```

The current reader checks that required metadata dimensions exist, reads the
expected byte counts, verifies that row pointers begin at zero and end at
`nnz`, requires nondecreasing row pointers, checks column-index bounds, and
rejects non-finite values.

Additional analysis-level validation should confirm:

1. `cls` contains no missing marker matches.
2. LD dimensions equal the intended marker count.
3. `row_ptr` has length $m+1$.
4. `col_idx` and `values` have equal length.
5. the final row pointer equals `nnz`.
6. returned `index_base` matches how `col_idx` is being inspected.
7. the upper-triangle and implicit-diagonal conventions are understood.
8. values are finite signed correlations and remain within plausible
   correlation bounds.
9. `n_used`, thresholds, windows, and marker count match the intended run.
10. `stats$wy`, every `stats$ww` vector, annotations, and posterior rows use
    exactly the same marker order.

The reader can validate structural properties but cannot prove that the BED
source, allele frequencies, sample rows, phenotypes, annotations, or marker
identities are scientifically aligned. Retain that provenance separately.

## How `stblr_csr()` Consumes the Prefix

The public model handoff is short:

```r
fit <- stblr_csr(
  stats = stats,
  Glist = Glist,
  scheduled = FALSE
)
```

During setup, the current ST-BLR CSR implementation:

1. checks that metadata marker count matches the model marker count;
2. reads the zero-based upper-triangle arrays;
3. validates row pointers, column bounds, finite correlations, and positive
   `stats$ww`;
4. ignores any explicit self-pairs if encountered;
5. converts retained $r_{ij}$ to
   $r_{ij}\sqrt{ww_iww_j}$; and
6. creates a symmetric in-memory neighbor structure for residual updates.

For marker effect $b_i$, the diagonal residual contribution uses
$ww_i b_i$, while retained off-diagonal neighbors use the converted
cross-product values. Missing off-diagonal entries are treated as zero in the
sparse approximation.

Annotation-aware CSR wrappers use the same LD prefix and marker-order
contract. Their differences concern prior structure, not CSR construction.

## Scheduled Sparse Updates

`stblr_csr(..., scheduled = TRUE)` uses a scheduled marker-update
implementation that can revisit likely null markers less frequently and wake
retained LD neighbors after an effect change. Settings such as
`full_sweep_every`, `candidate_threshold`, `candidate_lifetime`,
`null_skip_base`, `null_skip_max`, and LD-neighbor wake-up controls affect the
sampler's computational schedule.

These controls are separate from CSR construction settings:

- `r2_threshold` and distance windows determine which LD edges exist;
- scheduling controls determine when markers and retained neighbors are
  reconsidered during MCMC.

Both can affect finite-run behavior and performance. The statistical prior is
unchanged by choosing a scheduled path, but aggressive sparse scheduling must
be checked for adequate mixing and sensitivity. See
[Single-trait models](single_trait_models.html) for the scheduling controls.

## Sparse LD as an Approximation

The sparse matrix replaces unretained off-diagonal relationships with zero.
Approximation enters through:

- $r^2$ thresholding;
- marker-index and physical-distance windows;
- finite-sample LD estimation;
- allele-frequency estimation and missing-genotype handling;
- 32-bit storage of retained correlation values; and
- any difference between the sample or scaling used for LD and sufficient
  statistics.

Increasing `r2_threshold` or narrowing windows usually reduces `nnz`, runtime,
and disk use, but can remove LD needed to represent the conditional marker
likelihood adequately. Lower thresholds and wider windows preserve more LD at
greater computational cost. There is no universally correct threshold; its
adequacy depends on marker density, LD structure, sample size, phenotype
architecture, and inferential target.

## BED-Versus-CSR Comparison and Reproducibility

When both paths use the same BED source, markers, samples, phenotype,
standardization, and priors, `stblr_bed()` and `stblr_csr()` should
usually show qualitatively comparable posterior patterns. Exact equality is
not expected because:

- the CSR path omits unretained LD;
- BED and CSR samplers maintain residual information differently;
- update scheduling and initialization can differ;
- retained correlations use finite precision; and
- MCMC introduces Monte Carlo variation.

A comparison should examine PIP rankings, posterior mean effects, aggregate
variance summaries, and sensitivity to thresholds rather than equality of
individual samples.

For reproducibility, retain:

- immutable identifiers for BED inputs and selected samples;
- marker IDs in exact CSR order;
- `cls`, `rows`, allele frequencies, and positions;
- sufficient-statistic dimensions and scaling choices;
- all files belonging to `ld_prefix`;
- the writer's returned summary and metadata;
- package version and platform information; and
- model priors, MCMC settings, scheduling controls, and seeds.

The current workflow scripts use demonstration-scale settings. Production
analyses require sensitivity checks for LD construction and sampler settings,
longer chains, and convergence diagnostics.
