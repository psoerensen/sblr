ST-BLR Interface and Output Map

Author
Affiliation

Peter Sørensen

Aarhus University

This note is a compact map of the current ST-BLR user-facing interfaces, shared data object, model families, standardized outputs, and post-processing helpers. It is intentionally not a replacement for function help pages.

Main Modelling Interfaces

  • stblr_csr(): summary-statistics CSR backend using stats and sparse LD from Glist or an explicit ld_prefix.
  • stblr_bed(): individual-level PLINK/BED backend using genotype information from Glist.
  • stblr_csr_annot(): unified annotation-aware CSR backend using annotation_model = "prior", "learned", "group", or "sbayesrc".

stblr_bed_marker() remains available as a lower-level direct BED marker interface, but the high-level BED model entry point is stblr_bed().

Shared Data Object

Glist is the common carrier for genotype and marker metadata used by both CSR and BED workflows. In current code, relevant fields include:

  • Glist$bedfiles, the PLINK BED file paths used by BED and preparation helpers;
  • Glist$n, the number of BED individuals;
  • Glist$ids and optionally Glist$idsLD, used for sample matching;
  • Glist$rsids, marker IDs in BED-file order by chromosome/file;
  • Glist$rsidsLD, selected LD/model marker IDs by chromosome/file;
  • Glist$af, allele frequencies used for marker standardization and MAF dependent calculations;
  • Glist$sparseLD, added by make_sparse_ld(), with prefix, chr, bed_files, cls, af, rows, max_distance_bp, max_distance_variants, r2_threshold, and block_size.

For sparse-LD CSR models, marker-level information such as MAF must be aligned to the LD marker order. The package preparation helpers use positional alignment equivalent to:

idx <- match(Glist$rsidsLD[[chr]], Glist$rsids[[chr]])

Do not use %in% as the recommended alignment operation because it loses the requested LD marker order.

CSR Workflow

  1. Prepare or load a BED-backed Glist.
  2. Compute summary statistics with make_summary_stats().
  3. Compute sparse LD with make_sparse_ld().
  4. Fit summary-statistics BLR models with stblr_csr() or annotation-aware CSR models with stblr_csr_annot().
stats <- make_summary_stats(
  Glist,
  y,
  nthreads = nthreads
)

Glist <- make_sparse_ld(
  Glist = Glist,
  out_prefix = file.path(data_dir, "ld_test"),
  pos_bp = NULL,
  max_distance_bp = 0,
  max_distance_variants = 1000,
  r2_threshold = 0.001,
  block_size = 1024,
  nthreads = 4
)

fit_csr <- stblr_csr(
  stats = stats,
  Glist = Glist,
  method = "bayesC"
)

make_summary_stats() computes marker-trait summary statistics used by stblr_csr(). make_sparse_ld() computes disk-backed sparse LD and stores sparse-LD metadata in Glist$sparseLD. The updated Glist is then passed to stblr_csr() and related CSR functions.

BED Workflow

  1. Prepare or load a BED-backed Glist.
  2. Fit individual-level BLR models using stblr_bed().
  3. Use standardized output fields where available.
fit_bed <- stblr_bed(
  Glist = Glist,
  y = y,
  method = "bayesC"
)

stblr_bed() supports method = "bayesC" and method = "bayesR". Its current arguments include phenotype data y, Glist, optional chr, cls, rows, scale, MCMC controls, BayesC prior controls, BayesR mixture controls, and BED scheduled-chain controls. covar is not currently adjusted by this interface; pass pre-adjusted phenotypes. chain_seeds are not currently supported by the BED scheduled-chain backends.

selection_s Support

Fixed global selection_s and sampled trait-specific selection_s are supported for:

  • csr_bayesc;
  • csr_bayesr;
  • csr_sbayesrc.

They are not supported for:

  • csr_scheduled_bayesc;
  • csr_prior_bayesc;
  • csr_annot_bayesc;
  • csr_group_bayesc;
  • BED backends.

Sampled-S defaults are:

selection_s_init = 0
selection_s_prior = c(-3, 2)
selection_s_proposal_sd = 0.35

CSR effects are on the standardized-genotype scale. The MAF-dependent prior scale is:

q_j(S) = h_j^(S + 1)
h_j = 2 p_j (1 - p_j)

Standardized Output Fields

Model outputs are standardized across backends where possible:

  • fit$dm: marker-by-trait posterior inclusion probability or non-null probability.
  • fit$bm: marker-by-trait posterior mean effect.
  • fit$vbs: posterior trace of marker-effect variance.
  • fit$vgs: posterior trace of genetic variance.
  • fit$ves: posterior trace of residual variance.
  • fit$vle: posterior trace of linkage-equilibrium contribution, where returned.
  • fit$vld: posterior trace of LD contribution, where returned.
  • fit$input: backend, model, settings, and metadata.
  • fit$chains: optional compact chain-level output when supported and keep_chains = TRUE.

BayesR and SBayesRC outputs:

  • fit$comp_prob: marker-by-component posterior probabilities by trait.
  • fit$dm_component_mean: posterior mean component/effect-class summary.
  • BayesR null component: component_0.
  • SBayesRC null component: gamma_0.00.

Annotation-aware outputs are model-specific and may include:

  • fit$annotation_summary;
  • fit$annotation_pi;
  • fit$annotation_effects;
  • fit$annotation_prior;
  • fit$eta_pi, fit$eta_vb for learned annotation BayesC;
  • fit$group_pi, fit$group_vb_multiplier, fit$group_nincluded, fit$group_size for group BayesC;
  • fit$alpha, fit$sigmaSqAlpha, and fit$ncomp for SBayesRC-style fits;

Sampled-S outputs:

  • fit$selection_s;
  • fit$selection_s_sd;
  • fit$selection_s_min;
  • fit$selection_s_max;
  • fit$selection_s_trace;
  • fit$selection_s_acceptance.

With keep_chains = TRUE, supported CSR chain objects include:

  • fit$chains[[trait]][[chain]]$selection_s;
  • fit$chains[[trait]][[chain]]$selection_s_acceptance.

Fine-Mapping, LD-Swap, and Credible Sets

LD-swap diagnostics are available through fit$ld_swap and chain-level ld_swap / ld_swap_chains output when updateLDswap = TRUE and the backend supports it. LD-swap is a sampler mixing diagnostic and proposal mechanism, not a standalone credible-set object.

PIP is represented by fit$dm. Credible sets are constructed by helper functions such as make_credible_sets(), make_credible_sets_from_ld(), and make_multisignal_credible_sets_from_ld() from PIPs and LD. They are workflow/helper-level diagnostics unless a specific fine-mapping helper returns them in its own post-processing object.

make_credible_sets() requires a fit containing marker PIPs in fit$dm. It can use a supplied dense LD matrix or, for CSR workflows, use Glist$sparseLD$prefix to extract regional dense LD from disk-backed sparse LD. It defines automatic loci around high-PIP markers when explicit sets are not supplied. Credible-set probability is cumulative marginal PIP within the selected LD neighborhood, reported as cs_pip; the helper returns summary, nested sets, locus_sets, loci, parameters, and the resolved trait.

## Fine-Mapping, LD-Swap, and Credible Sets

LD-swap diagnostics are available through `fit$ld_swap` and chain-level
`ld_swap` / `ld_swap_chains` output when `updateLDswap = TRUE` and the backend
supports it. LD-swap is a sampler mixing diagnostic and proposal mechanism,
not a standalone credible-set object.

PIP is represented by `fit$dm`. Credible sets are constructed by helper
functions such as `make_credible_sets()`, `make_credible_sets_from_ld()`,
and `make_multisignal_credible_sets_from_ld()` from PIPs and LD. They are
workflow/helper-level diagnostics unless a specific fine-mapping helper returns
them in its own post-processing object.

`make_credible_sets()` requires a fit containing marker PIPs in
`fit$dm`. It can use a supplied dense LD matrix or, for CSR workflows, use
`Glist$sparseLD$prefix` to extract regional dense LD from disk-backed sparse
LD. It defines automatic loci around high-PIP markers when explicit `sets` are
not supplied. Credible-set probability is cumulative marginal PIP within the
selected LD neighborhood, reported as `cs_pip`; the helper returns `summary`,
nested `sets`, `locus_sets`, `loci`, `parameters`, and the resolved `trait`.
